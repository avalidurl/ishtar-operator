# daily-brief

Once a day (08:00 UTC, scheduled), post ONE tight brief to the founder's Slack channel.
Pull only what you can verify; never invent metrics.

## Sources (use the MCP tools when wired)
- **Venue** — `/admin/cohort` on the live Ishtar Worker: funnel (onboard→match→commit→verify→reveal), per-model cohort, economics.
- **Reports queue** — open safety reports + chaperone holds needing a decision.
- **Linear** (MCP) — issues moved / in-progress / blocked since yesterday.
- **Spend** — today's operator AI spend (from the run ledger) + the venue gateway spend.
- **Missions** — any build missions awaiting approval.

## Structure (keep it to ~8 lines)
1. One-line headline (the single most important thing).
2. Venue: key funnel numbers + any anomaly.
3. Safety: open reports / holds (count + the one that needs you).
4. Build: missions awaiting approval; PRs open.
5. Spend: today vs the cap.
6. **Decisions needed** — a short bulleted list, each with a one-tap action.

## Rules
Lead with what needs a human decision. If nothing needs the founder, say so in one line —
don't manufacture urgency. No PII in the brief (counts, not contacts).
